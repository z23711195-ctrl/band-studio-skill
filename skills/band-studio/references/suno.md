# Suno 执行与版本连续性

本包没有 Suno API 客户端，也不携带登录状态。使用当前环境实际提供的浏览器控制、正式连接器或已配置且可验证的接口。先读对应工具/技能说明，不沿用过时字段、模型名或滑杆范围。

## 提交前

确认账号与选中的原录音/上一个版本，保留其来源标识。按目标选择当时界面实际支持的覆盖、续写或编辑方式。

核对原词、风格、人声/器乐选项、保留要求与排除风格之间有无冲突。对已经填入或清空的歌词框，回读实际文本；工具返回成功不保证网页框内容变了。

检查原音频已经真正绑定。不能在来源缺失时直接普通生成，再称是按原动机做出的改编。提示词不能保证逐音逐拍保留。

Jev 已配置且文字处理在授权范围时，按 [jev.md](jev.md) 的 `preflight` 对要求与实际回读字段做一批语义检查。将 `excluded_styles` 与正向风格分开；未观察字段省略。先解决冲突与未知项，再由主协调者提交。结果只检查所给文本，不能证明音频绑定或生成质量；没有 Jev 时按上述同样要求手动检查。

## 有界排障

- 控制连接断开：重新取得当前控制端的标签状态；保留草稿，不立刻要求重登。
- 登录页/验证码：只处理实际出现的认证步骤，复用用户已有授权。
- 本地文件选择权限：按当前浏览器工具说明诊断；不要反复要求开启已确认开启的开关。
- 文件已传到服务但匹配/政策拒绝：记录具体拒绝并停止这条上传路径；不能通过改速、改调、加噪或换端点规避。
- 网络/限额问题：记录具体响应和当前提交状态。状态不明时先查结果，避免重复扣费提交；不自动开通付费。

同一失败只在有新证据或修正时重试。无法继续时保留具体草稿、原文件位置和下一步，不把阻塞描述成歌曲完成。

## 结果与试听

实际生成完成后，核对来源、版本、结果 URL、时长与页面可用状态。用户要在线试听时给核验过的链接；要求音频文件时才按服务权限下载。

尊重用户的播放偏好。播放器控件存在或进度移动不等于你听过；有真实音频证据才判断咬字、旋律保留、风格和配器。把“生成完成”“内容已核验”“用户认可”分开记录。

每轮保存简短记录：输入版本、原词/提案、实际字段值、这轮改变了什么、真实结果链接、核验方法、仍待用户试听的点。不要把账号、cookie、验证码或密钥写进记录。
